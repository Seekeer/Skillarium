# Добавить общий скилл в каталог

Работай в agent-skills-updater на i3, прочитай README и server/catalogs.json.
Выбери каталог по имени; если он один, уточнение не нужно. Управляющий скилл
остаётся здесь, каталог получает только реестр и развёрнутый клиент.

1. Определи Git URL, подпапку скилла и полный ref (refs/heads/main или тег).
   Для одиночного SKILL.md допустим версионный HTTPS URL. При коллекции
   уточни скилл только при неоднозначности. Файлу/архиву сначала нужен
   согласованный опубликованный источник содержимого; payload сюда не добавляй.
2. Спроси: «Автоматически принимать новые версии этого источника после
   технической проверки раз в сутки на i3?» Варианты «Да» и «Нет, только
   после ручного одобрения». Явно данный выбор не переспрашивай. Пока ответа
   нет, подготовь источник без регистрации с выдуманным auto_update.
3. Выполни `python3 server/manage.py --catalog <catalog> register <name>
   --git-url <url> --path <subdir> --ref <full-ref> --auto-update yes|no
   --publish`. Для одиночного файла используй --url. Команда проверяет
   содержимое, закрепляет revision и content_sha256, разворачивает клиент
   и публикует изменения только в выбранном каталоге. Если запись уже есть,
   используй процедуру просмотра/одобрения версий вместо повторной регистрации.
4. Проверь опубликованный commit, запись sources.json и совместимость скилла
   с агентами/ОС. Проверка структуры/хеша не оценивает смысл инструкций.
   Для проверки локальной установки запусти install.sh --link-only из каталога.
   Остальные подключённые компьютеры получат запись своим ежечасным запуском.

Секреты храни в механизме Git пользователя. При конфликте имени другого
источника согласуй замену/новое имя. Ручные изменения копий клиента и чужие
коммиты сохраняй. Просьба добавить скилл включает публикацию этой регистрации;
force-push не используется. Если ежедневный серверный таймер отсутствует,
сообщи об этом: флаг auto_update сам по себе расписание не создаёт.
