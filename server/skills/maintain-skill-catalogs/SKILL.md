# Обслуживание каталогов

Прочитай README. Эталон клиентов лежит в client/, каталоги указаны в
server/catalogs.json. Пути относительны к этому конфигурационному файлу.
Для нового каталога укажи name/path/remote/branch по подтверждённой Git-копии
с sources.json версии 2 и настроенным upstream. Произвольные компьютеры
из Fleet автоматически каталогами не становятся.

Начни с `python3 server/manage.py status` и `maintain --dry-run`. Для
развёртывания только клиента используй `--catalog <name> deploy-client
--publish`; для полного обслуживания — `maintain --apply-auto --publish`.
Последний проверяет источники и принимает только разрешённые обновления.
Обе команды также заполняют отсутствующие skills/<name>/ закреплёнными
версиями: клиенты сами ничего не скачивают. Перенос старого формата
customizations выполняется с проверкой хешей и сохранением Git-истории.

Изменения клиентских скриптов делай в client/. Ручную правку развёрнутой
копии сервер сохраняет как конфликт. Сравни её с эталоном и перенеси нужную
доработку в client/; не обходи конфликт автоматическим reset/clean. Первое
подключение разрешает совпадающие существующие файлы и добавляет манифест.
Чужой несовпадающий файл нужно отдельно разобрать до подключения.

Регистрацию источников выполняй по add-shared-skill, одобрение — по
check-skill-updates. Проверь публикацию и отсутствие лишних изменений в
каталоге. Серверный таймер устанавливается `bash server/install.sh` только
на i3. Клиентский таймер остаётся отдельным и ставится из самого каталога.
