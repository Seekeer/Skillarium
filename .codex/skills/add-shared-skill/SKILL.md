# Добавить общий скилл

Работай в отдельном репозитории agent-skills. Корень определяй через Git;
прочитай `README.md`. Этот управляющий скилл остаётся проектным. Общие
устанавливаемые скиллы хранятся в `skills/` и доступны через пользовательские
ссылки Codex, OpenCode и Claude Code.

## Импорт

1. Получи URL, файл, архив или код. При ссылке на коллекцию уточни скилл
   только если выбор неоднозначен. Загрузи содержимое во временную папку
   вне каталогов обнаружения. Проверь пути и ссылки архива перед распаковкой;
   импортируемые команды не выполняй как часть установки.
2. Перенеси `SKILL.md`, необходимые зависимости и лицензию в `skills/<name>/`.
   Проверь YAML-поля `name` и `description`, совпадение имени папки с `name`,
   относительные ссылки и совместимость с агентами/ОС. Сохрани нужные
   `scripts/`, `references/`, `assets/` и метаданные; секреты оставь вне Git.
   При совпадении имени и другом источнике согласуй замену или новое имя.
3. Спроси: «Автоматически обновлять этот скилл из источника раз в сутки?»
   Варианты: «Да» и «Нет, только вручную». Явный выбор в текущем запросе
   учитывай без повторного вопроса. Во время ожидания подготовь и проверь
   файлы; зависимые действия выполняй после ответа. Для файла без постоянного
   источника предложи указать URL, если пользователь хочет автообновление.
4. Сохрани источник, установленную версию, хеши файлов и выбор в `sources.json`
   по [правилам обновления](references/updates.md). Проверь diff и структуру
   скилла; используй валидатор skill-creator, если он доступен.

## Публикация и доставка

Просьба добавить скилл в этот репозиторий включает commit/push относящихся к
нему файлов. Сохрани чужие изменения, используй настроенный remote и ветку.
При отсутствующем remote подготовь локальный коммит и сообщи, что публикация
ожидает адреса Git-репозитория; remote не выдумывай. Совмещай отклонённый push
без force-push. Конфликты оставь для решения с сохранением локальных данных.

Запусти `bash install.sh --link-only` на Linux либо `install.ps1 -Mode Link`
на Windows и проверь ссылку в обоих пользовательских каталогах. Остальные
подключённые компьютеры получают commit по своему ежечасному расписанию.
Для этого не нужны SSH, RDP или связь между T3-окружениями. Не объявляй
установку на другом компьютере проверенной без фактического отчёта от него.

При согласии на обновления настрой расписание из
[references/updates.md](references/updates.md). В запланированном запуске
используй сохранённый выбор без повторного вопроса. В результате сообщи
имя, источник, commit, состояние публикации, локальных ссылок и автообновлений.
