# Общие скиллы

Этот Git-репозиторий содержит готовые папки `skills/<name>/`, реестр
`sources.json` и установщики Linux/Windows. Внешние источники скачивает,
проверяет и обновляет сервер
[agent-skills-updater](https://gitea.example.org/dim/agent-skills-updater).
Клиент работает только с этим репозиторием.

## Подключение компьютера

Клонируйте каталог под пользователем, запускающим агентов. На Linux нужны
Git, Bash, jq, flock и обычные утилиты файловой системы:

```bash
bash install.sh
```

На Windows 10/11 нужны Git, PowerShell 5.1+ и включённый Windows Script Host
с поддержкой VBScript. Используйте локальный диск;
администратор и Developer Mode не требуются:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик создаёт ссылки `.agents/skills/<name>` и `.claude/skills/<name>`
прямо на `skills/<name>/` Git-копии (в Windows — junctions), затем включает
ежечасную синхронизацию. Клиент не обращается к внешним источникам, не
скачивает архивы и не создаёт кеш версий. Python не нужен.

Linux-таймер работает при активном пользовательском systemd; для работы
после выхода требуется linger. Windows-задача работает при входе пользователя.
Планировщик запускает `scripts/sync-hidden.vbs` через `wscript.exe`: PowerShell
создаётся сразу со скрытым окном, а его код завершения возвращается планировщику.
Служба Windows не требуется. После получения обновления очередной успешный
`-Mode Sync` переводит существующую задачу на скрытый запуск, сохраняя расписание.
Задача не создаётся заново, если ранее была удалена через `-Mode Uninstall`.
WSL подключается отдельно Linux-установщиком. Git в фоне должен работать
без запроса пароля. Не переносите Git-копию без исправления ссылок и расписания.

## Изменение скилла

Редактируйте установленный скилл через `.agents/skills/<name>` или
`.claude/skills/<name>`: это сразу меняет файлы в Git-копии. При синхронизации
клиент коммитит изменения только зарегистрированных папок,
получает изменения из origin, объединяет совместимые коммиты, отправляет
результат и проверяет ссылки.
Остальные станции получают файлы при своей синхронизации. Нужен доступ
к этому Git-репозиторию на запись. Реестр изменяет сервер: клиент его не правит.

Независимые коммиты объединяются обычным Git merge во временной рабочей копии.
При конфликте локальный коммит сохраняется до ручного разбора; маркеры слияния
в установленные файлы не попадают. Пока конфликт не разобран, синхронизация
останавливается целиком: обновления не приходят, новые правки не публикуются.
Приложение показывает такой конфликт и обе версии каждого файла; для каждого
файла выбирается своя версия, версия библиотеки или отредактированный итог.
Итог фиксируется коммитом слияния и сразу публикуется. Rebase, reset и force-push не используются.
Git ignore соблюдается; игнорируемые локальные файлы не отправляются.
Неудачный сетевой push повторяется. Staged-файлы,
неопубликованные ручные коммиты, незарегистрированные папки и изменения
вне `skills/<name>/` автоматически не отправляются. Удаление всего скилла
или `SKILL.md` требует ручного решения.

Внешнее обновление с доработками отмечается сервером как `upstream-conflict`.
Сервер сохраняет вашу папку до явного решения. Команды просмотра и разрешения
описаны в README updater. Собственный скилл без внешнего URL добавляется там
через `register-local <name> --directory <folder> --publish`; нужны `SKILL.md`
с совпадающим именем и файлы скилла внутри папки.

## Проекты

Скилл библиотеки можно подключить только к нужным проектам. Проект получает
ссылки `.agents/skills/<name>` и `.claude/skills/<name>` на ту же папку
`skills/<name>/`: правка через любой проект сразу видна всем подключениям
этого компьютера и публикуется как обычная правка скилла.

Команды — серверная часть раздела «Проекты» локального приложения:

```bash
bash projects.sh register <папка-проекта>
bash projects.sh bind <папка-проекта> <skill>
bash projects.sh unbind <папка-проекта> <skill> [global|library]
bash projects.sh global <skill> on|off
bash projects.sh status
bash projects.sh conflicts
bash projects.sh resolve <решение.json>
```

На Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\projects.ps1 <команда> ...`
(ссылки — junction). `status` и ответ на последнее отключение выводят JSON.
Код 3 означает, что отключается последний проект и нужен выбор: `global`
(доступен глобально) или `library` (только в библиотеке); без выбора ничего
не меняется. Код 4 — подключение сохранено, но не применено из-за чужого
содержимого; подробности в `status`.

`conflicts` повторяет слияние синхронизации во временной рабочей копии и
выводит JSON с конфликтующими файлами: локальная версия берётся из рабочего
дерева, версия библиотеки — из `origin`. `resolve` принимает JSON
`{upstream, files: [{path, take, mine, library, text}]}`, где `take` —
`mine`, `library` или `edited`, а `mine` и `library` — показанные идентификаторы
объектов. Сначала коммитятся локальные правки; если версии изменились с момента
показа, ничего не сливается и возвращается код 5.

Новый скилл по умолчанию доступен глобально. Первое подключение через
команды снимает глобальные ссылки после успешного создания проектных, если
глобальный доступ не задан вручную; ручной выбор (`global`, ответ на вопрос
о последнем проекте) сохраняется дальше. Изменения списка вне команд,
например при переключении ветки, глобальную настройку не меняют.

В Git проекта хранится только `.agent-skills.json` с именами скиллов;
команды меняют рабочее дерево и не создают коммитов. Ссылки исключаются
локальным `info/exclude` проекта. Пути проектов, глобальный выбор и владение
ссылками хранятся локально (`$XDG_STATE_HOME/agent-skills/bindings.json`,
на Windows `%LOCALAPPDATA%\agent-skills\bindings.json`) и не публикуются.
Каждый клон и worktree регистрируется отдельно; после клонирования достаточно
`register`. Фоновая синхронизация применяет текущие списки
зарегистрированных папок. Недоступная папка сохраняет регистрацию.
Клиент удаляет только свои ссылки с прежней целью; чужие папки и ссылки
сохраняются как конфликт. Обычные папки скиллов внутри проектов не
импортируются.

## Управление

Linux: `bash install.sh --sync-only`, `--link-only` (без Git-синхронизации),
`--uninstall` (отключает расписание, сохраняя ссылки).
Windows: `install.ps1 -Mode Sync`, `-Mode Link` или `-Mode Uninstall`.
Локальные режимы Link не коммитят и не отправляют файлы.

Linux-журнал: `journalctl --user -u agent-skills.service -n 30`;
расписание: `systemctl --user list-timers agent-skills.timer`.
Windows: `Get-ScheduledTask -TaskName 'AgentSkills-Hourly-*' | Get-ScheduledTaskInfo`.

Чужие установки и ссылки сохраняются с сообщением о конфликте. При переходе
со старого клиента принадлежащие ему ссылки из кеша переводятся на Git-папки.
Совместимые локальные доработки старого кеша импортируются и публикуются;
при несовпадении баз обе копии сохраняются. Сам старый кеш не удаляется.
Если папка отсутствует в каталоге, клиент сообщает об ошибке: заполнить её
должен сервер. Удаление записи из реестра не удаляет старую ссылку автоматически.

Новые инструкции надёжно обнаруживаются в новом сеансе агента.
Совместимость скриптов с ОС проверяется отдельно. Git сохраняет точные байты
скиллов, включая CRLF и бинарные файлы; Git-метаданные и вложенные ссылки
внутри скиллов не поддерживаются.

Перед автокоммитом клиент проверяет совместимость путей с Windows: запрещены
device names (`CON`, `AUX`, `COM1` и другие, в том числе с расширениями),
символы `< > : " \\ | ? *`, управляющие символы, завершающие точки/пробелы
и коллизии регистра файлов или папок. При отказе файлы сохраняются локально.
Эти правила действуют и на Linux, чтобы правка не сломала checkout Windows.
