# Skillarium

Общая библиотека скиллов для агентов (Codex, Claude Code) на всех ваших
компьютерах и во всех проектах. Skillarium — это движок: нативные клиенты
Linux/Windows (`install.*`, `projects.*`, `scripts/`), сервер (`server/`),
приложение (`app/`) и шаблон библиотеки (`templates/library/`).

Ваши скиллы живут не здесь, а в **вашей библиотеке** — отдельном
Git-репозитории в вашей Gitea: папки `skills/<name>/`, реестр `sources.json`,
общая конфигурация `agent-skills.json` и базы внешних версий `upstream/`.
Форк Skillarium не нужен: движок и приложение обновляются из выпусков этого
репозитория, а библиотека остаётся вашей.

Все автоматические публикации идут через ветки `agent-skills/...` и pull
request с автоматическим слиянием. Основная ветка защищена, прямой push в неё
не выполняется. Правки скиллов принимаются от любой подключённой машины после
технических проверок; закрепления внешних версий и базы `upstream/`
принимаются только от машины, назначенной сервером в `agent-skills.json`.
Политику обновлений внешнего скилла может переключить любая машина.

## Установка

### Сервер библиотеки (Linux, без графики)

Одна команда на машине, которая будет сервером (у автора — `i3`). Нужны Git,
Python 3.9+, jq, curl, flock, пользовательский systemd и linger
(`sudo loginctl enable-linger $USER`); чего не хватает, установщик подскажет.

```bash
curl -fsSL https://github.com/Seekeer/Skillarium/releases/latest/download/skillarium.sh | bash -s -- server --repo https://gitea.example.org/owner/skills.git --bot skills-bot
```

Установщик:

- ставит движок в `~/.local/share/skillarium` и команду `skillarium`;
- спрашивает токен Gitea владельца библиотеки (`--token-file` — из файла) и
  кладёт его в Git credential helper;
- создаёт репозиторий, если его нет; пустой заполняет шаблоном библиотеки;
  существующую библиотеку подключает и, если её обслуживала другая машина,
  передаёт роль сервера этой (административный PR);
- включает Actions, защищает `main` обязательной проверкой `policy` и
  требованием актуальности ветки;
- с `--bot <имя>` создаёт служебного пользователя для клиентов (нужен токен
  администратора Gitea) и один раз показывает его токен;
- проверяет раннер Actions; `--runner` регистрирует `act_runner` на этой же
  машине (раннеру нужен доступ к GitHub: проверка PR скачивает закреплённый
  выпуск политики);
- включает таймеры: обслуживание раз в сутки и самообновление движка раз в
  час; `--with-client` добавляет ещё и синхронизацию скиллов на этой машине;
- печатает команды подключения клиентов и записывает их в README библиотеки.

Повторный запуск ничего не дублирует: им же чинят и обновляют установку.
Клон библиотеки на сервере — `~/Skillarium/library` (`--path` меняет).
Пустой репозиторий получает первый коммит прямым push — до того, как
установщик включает защиту `main`; дальше всё идёт только через PR. Если в
глобальной настройке Git нет credential helper, установщики (сервера и
клиента) включают `store` (`~/.git-credentials`, доступен только вам; на
Windows — Git Credential Manager, если он есть) и сообщают об этом. Токен бота
показывается один раз и хранится в `~/.config/skillarium/bot-token` (права
0600), чтобы повторный запуск мог сказать, где он.

### Клиенты

Команды печатает установщик сервера; токен в них не входит — установка
спрашивает его сама (обычно токен служебного бота).

Windows 10/11 (PowerShell, без прав администратора):

```powershell
& ([scriptblock]::Create((irm https://github.com/Seekeer/Skillarium/releases/latest/download/skillarium.ps1))) client -Library https://gitea.example.org/owner/skills.git
```

Linux:

```bash
curl -fsSL https://github.com/Seekeer/Skillarium/releases/latest/download/skillarium.sh | bash -s -- client --library https://gitea.example.org/owner/skills.git
```

Клиентская установка ставит движок и приложение того же выпуска (NSIS в
профиль пользователя; на Linux — AppImage в `~/.local/bin` с пунктом меню),
проверяет, что токен может писать в библиотеку, клонирует её в
`~/Skillarium/library` (`-Path`/`--path`; готовый клон того же репозитория
принимается), записывает конфиг Skillarium, раскладывает ссылки скиллов и
включает ежечасную синхронизацию. `--no-app` на Linux ставит только движок с
ежечасным самообновлением — для машин без графики. На Windows `-NoApp`
ставит такую же ежечасную задачу самообновления (`skillarium enable-updates`).

Приложение можно скачать и отдельно со страницы выпусков: при первом запуске
оно само предложит подключить библиотеку (адрес, токен, папка) — те же шаги.

### Обновления

- Приложение обновляется само (electron-updater) и предлагает перезапуск; с
  ним обновляется и движок, который оно несёт: при запуске приложение
  раскладывает свой движок в `versions/<версия>` и переключает `current`.
- Машины без приложения обновляет `skillarium self-update` по таймеру.
- Приложение не откатывает движок: если `current` новее его собственного
  движка (например, после `self-update --channel beta`), он остаётся.
- На Windows `current` — junction, и его замена занимает два шага (удалить и
  создать); синхронизация, попавшая ровно в этот момент, пропускает один час.
- `skillarium add <ссылка или папка>` — добавить скилл в библиотеку: ссылка
  на репозиторий, папку скилла или его SKILL.md, или своя папка (нужен
  Python; внешний источник регистрирует назначенный сервер, см.
  [server/README.md](server/README.md#команды-сервера)).
- `skillarium status` — версия, канал, формат библиотеки и режим;
  `skillarium rollback` — вернуться на предыдущую версию (она пропускается до
  следующего выпуска); `skillarium self-update --channel beta` — канал
  предварительных выпусков.
- Библиотеку поднимает до нового формата только сервер. Машина со старым
  движком в это время работает только на чтение: скиллы есть, правки не
  публикуются, приложение предлагает обновиться.

Выпуски публикуются по тегу `v<версия>` (`.github/workflows/release.yml`):
установщики приложения, архивы движка, `skillarium.sh`/`skillarium.ps1` и
`latest.json`. План распространения —
[.scratch/skillarium-distribution/plan.md](.scratch/skillarium-distribution/plan.md),
переход старой библиотеки со встроенным движком — [docs/migration.md](docs/migration.md).

## Подключение компьютера вручную

Обычно не нужно: установка выше делает то же самое. Требования: на Linux —
Git, Bash, jq, curl, flock; на Windows 10/11 — Git, PowerShell 5.1+ и Windows
Script Host с VBScript, без администратора и Developer Mode. Команды
выполняются из установленного движка (`current`) с явной библиотекой:

```bash
bash ~/.local/share/skillarium/current/install.sh --library ~/Skillarium/library
```

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Skillarium\current\install.ps1" -Library "$env:USERPROFILE\Skillarium\library"
```

Установщик создаёт ссылки `.agents/skills/<name>` и `.claude/skills/<name>`
прямо на `skills/<name>/` библиотеки (в Windows — junctions) и включает
ежечасную синхронизацию. Python клиенту не нужен; клиент не обращается к
внешним источникам. Git и API хостинга должны работать без запроса пароля:
клиент берёт учётные данные из Git credential helper (токен с правом записи).

Имя машины берётся из `git config agent-skills.machine`, иначе из имени
компьютера. Имена должны различать установки (например, Windows и WSL на одном
компьютере): `git config agent-skills.machine laptop-wsl`. Адрес API выводится
из origin; другой задаётся `git config agent-skills.api <url>/api/v1/repos/<owner>/<repo>`.

Linux-таймер работает при активном пользовательском systemd; для работы после
выхода нужен linger. Windows-задача работает при входе пользователя и запускает
`scripts/sync-hidden.vbs` через `wscript.exe` со скрытой консолью; очередной
`-Mode Sync` переводит старую задачу на этот запуск, сохраняя расписание.
Не переносите Git-копию без исправления ссылок и расписания.

## Правки скиллов

Редактируйте установленный скилл через `.agents/skills/<name>` или
`.claude/skills/<name>` — это файлы Git-копии. При синхронизации клиент
коммитит изменения папок `skills/<name>/` от имени `agent-skills/<машина>`,
объединяет их с основной веткой во временной рабочей копии, отправляет ветку
`agent-skills/sync/<машина>-<id>` и создаёт или обновляет один PR с
автослиянием. Подтверждать ничего не нужно; хостинг запускает проверки и
принимает PR. Остальные станции получают принятый результат при своей
синхронизации. Личные настройки автора Git не меняются.

Новая папка `skills/<name>/` с корректным `SKILL.md` (frontmatter с тем же
`name` и `description`) публикуется так же, без записи в реестр: сервер
зарегистрирует её как собственный скилл при очередном обслуживании.

Автоматически не публикуются: staged-файлы, неопубликованные ручные коммиты,
изменения вне `skills/<name>/` (код клиента, сервер, документация), файлы по
правилам Git ignore. Некорректный `SKILL.md`, несовместимые с Windows пути
(device names вроде `CON`, `AUX`, `COM1`, символы `< > : " \ | ? *`,
завершающие точки/пробелы, коллизии регистра) и удаление всего скилла дают
понятный отказ; файлы остаются на месте. Удаление скилла целиком — явная
административная операция.

При конфликте параллельных правок локальный коммит сохраняется, маркеры
слияния в установленные файлы не попадают. Rebase, reset и force-push не
используются. Без сети скиллы продолжают работать, правки сохраняются в
локальном коммите и публикуются при следующей синхронизации; повтор находит
уже отправленную ветку и PR и не создаёт дубликатов.

Пока такой конфликт не разобран, синхронизация останавливается целиком:
обновления не приходят, новые правки не публикуются. Приложение (`app/`,
раздел «Проекты») показывает это и открывает разбор в духе WinMerge: слева
ваша версия, справа версия общей библиотеки, внизу редактируемый итог. Для
каждого различия берётся левая, правая или обе версии, итог можно править
руками; удалённые и двоичные файлы берутся целиком. Итог проверяется как
скилл, фиксируется коммитом слияния и публикуется обычным PR-предложением.

## Внешние обновления

Внешние источники проверяет только назначенный сервер. Для каждого внешнего
скилла задана политика (`auto_update` в реестре):

- `auto` — совместимое обновление, в том числе чистое объединение с вашими
  доработками, применяется автоматически; вопрос возникает только при конфликте;
- `confirm` — каждое обновление ждёт вашего подтверждения.

Политику переключают с любого клиента, в обе стороны: в приложении — колонка
«Обновлять автоматически», в терминале — `bash install.sh --policy <skill>
auto|confirm` (Windows: `install.ps1 -Mode Policy -Skill <skill> -Policy
auto|confirm`). Меняется одна строка `sources.json`, публикация — обычным PR;
до его принятия приложение показывает «Ждёт принятия». Ожидающее обновление
после переключения на `auto` сервер применяет при ближайшем обслуживании.

Ожидающие обновления — ветки `agent-skills/update/<name>/<ключ>` с PR без
автослияния. Активные установки, включая серверную, до принятия не меняются.
Работайте с ними на любом клиенте (или попросите агента — встроенный скилл
`review-skill-updates`; встроенные скиллы движка лежат в `client/skills/`,
синхронизация ставит на них ссылки, а одноимённый скилл библиотеки важнее):

```bash
skillarium updates
skillarium review <skill>
skillarium approve <skill> <commit>
skillarium resolve <skill> <commit> keep-ours|take-upstream|merged
```

Это те же режимы установщика (`install.sh --updates|--review|--approve|--resolve`,
`install.ps1 -Mode Updates|Review|Approve|Resolve`) установленного движка для
библиотеки из конфига.

`review` показывает итоговый diff относительно текущей общей версии и
готовит копию для разбора в `.git/agent-skills-review/<skill>` (вне
установки; при конфликте — с маркерами). Одобряется точный показанный коммит:
если предложение, общая папка или входящая версия изменились, команда
откажет, а сервер подготовит новое предложение. Для `merged` отредактируйте
файлы в копии разбора и уберите маркеры. Отвязка от источника (`detach`)
выполняется на сервере: `python3 server/manage.py resolve`.

## Проекты

Скилл библиотеки можно подключить только к нужным проектам. Проект получает
ссылки `.agents/skills/<name>` и `.claude/skills/<name>` на ту же папку
`skills/<name>/`: правка через любой проект сразу видна всем подключениям
этого компьютера и публикуется как обычная правка скилла.

Команды — серверная часть раздела «Проекты» локального приложения:

```bash
bash projects.sh register <папка-проекта>
bash projects.sh bind <папка-проекта> <skill>
bash projects.sh unbind <папка-проекта> <skill> [global|library]
bash projects.sh global <skill> on|off
bash projects.sh status
bash projects.sh conflicts
bash projects.sh resolve <решение.json>
```

На Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\projects.ps1 <команда> ...`
(ссылки — junction). `status` и ответ на последнее отключение выводят JSON.
Код 3 означает, что отключается последний проект и нужен выбор: `global`
(доступен глобально) или `library` (только в библиотеке); без выбора ничего
не меняется. Код 4 — подключение сохранено, но не применено из-за чужого
содержимого; подробности в `status`.

`conflicts` повторяет слияние синхронизации во временной рабочей копии и
выводит JSON с конфликтующими файлами: локальная версия берётся из рабочего
дерева, версия библиотеки — из `origin`. `resolve` принимает JSON
`{upstream, files: [{path, take, mine, library, text}]}`, где `take` —
`mine`, `library` или `edited`, а `mine` и `library` — показанные идентификаторы
объектов. Сначала коммитятся локальные правки; если версии изменились с момента
показа, ничего не сливается и возвращается код 5. Итог, который больше не
является корректным скиллом, отклоняется до слияния.

Приложение: `cd app && npm ci && npm start` (Electron, React). UI-проверки:
`npm test` — Playwright запускает настоящее приложение против временной
библиотеки и проектов.

Новый скилл по умолчанию доступен глобально. Первое подключение через
команды снимает глобальные ссылки после успешного создания проектных, если
глобальный доступ не задан вручную; ручной выбор (`global`, ответ на вопрос
о последнем проекте) сохраняется дальше. Изменения списка вне команд,
например при переключении ветки, глобальную настройку не меняют.

В Git проекта хранится только `.agent-skills.json` с именами скиллов;
команды меняют рабочее дерево и не создают коммитов. Ссылки исключаются
локальным `info/exclude` проекта. Пути проектов, глобальный выбор и владение
ссылками хранятся локально (`$XDG_STATE_HOME/agent-skills/bindings.json`,
на Windows `%LOCALAPPDATA%\agent-skills\bindings.json`) и не публикуются.
Каждый клон и worktree регистрируется отдельно; после клонирования достаточно
`register`. Фоновая синхронизация применяет текущие списки
зарегистрированных папок. Недоступная папка сохраняет регистрацию.
Клиент удаляет только свои ссылки с прежней целью; чужие папки и ссылки
сохраняются как конфликт. Обычные папки скиллов внутри проектов не
импортируются.

## Управление

Команды выполняются из установленного движка (`current`), при необходимости
с `--library`/`-Library`.
Linux: `bash install.sh --sync-only`, `--link-only` (без Git-синхронизации),
`--status` (машина, сервер, ожидающая публикация и причина, предложения),
`--uninstall` (отключает расписание, сохраняя ссылки).
Windows: `install.ps1 -Mode Sync`, `-Mode Link`, `-Mode Status`, `-Mode Uninstall`.

Linux-журнал: `journalctl --user -u agent-skills.service -n 30`;
расписание: `systemctl --user list-timers agent-skills.timer`.
Windows: `Get-ScheduledTask -TaskName 'AgentSkills-Hourly-*' | Get-ScheduledTaskInfo`.

Чужие установки и ссылки сохраняются с сообщением о конфликте. Ссылки старого
клиента на кеш `versions/<name>/<hash>` переводятся на папки библиотеки,
совместимые доработки кеша импортируются; сам кеш не удаляется. Git сохраняет
точные байты, CRLF, бинарные файлы и права исполнения; Git-метаданные и
вложенные ссылки внутри скиллов не поддерживаются.

## Движок и библиотека

Установленный движок лежит в `~/.local/share/skillarium` (Windows:
`%LOCALAPPDATA%\Skillarium`): `versions/<версия>/` и ссылка `current`
(symlink, в Windows — junction), через которую идут расписания и команда
`skillarium`. Хранятся текущая и две предыдущие версии. Библиотека ищется в
таком порядке:

1. `--library <папка>` (`-Library` в PowerShell, `--repo` у `server/manage.py`,
   `server/run.sh` и `server/install.sh`);
2. переменная `SKILLARIUM_LIBRARY`;
3. папка самого движка, если она является библиотекой (старая раскладка,
   движок внутри библиотеки);
4. поле `library` в `~/.config/skillarium/config.json`
   (`%APPDATA%\Skillarium\config.json` в Windows).

Расписание установленного движка передаёт библиотеку явно. Старая раскладка
при синхронизации сама ставит Skillarium и переводит расписание на `current`
(мост, `scripts/bridge.*`; `SKILLARIUM_NO_BRIDGE=1` отключает), после чего
файлы движка убираются из библиотеки — см. [docs/migration.md](docs/migration.md).

`agent-skills.json` содержит `format` (по умолчанию 1). Если библиотека —
локальная или в `origin` — новее, чем понимает движок, всё, что пишет в неё
(синхронизация, публикация, одобрение и разрешение предложений, разбор
конфликтов), отказывается: скиллы продолжают работать, правки остаются
локальными. Сервер в таком случае ничего не обслуживает, а приложение
показывает предупреждение. Поддерживаемый формат задаётся в
`scripts/locate.*` и `server/hosting.py`; держите их равными.

`policy_engine` в `agent-skills.json` — версия и sha512 выпуска Skillarium,
чью политику запускает проверка PR библиотеки. Её поднимает только
назначенный сервер (`manage.py pin-policy`, ежедневно после самообновления), и
только вперёд.

Сервер, назначение роли, правила PR и миграции описаны в
[server/README.md](server/README.md).
