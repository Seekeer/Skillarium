# Agent Skills Updater

Исходный код системы доставки общих скиллов. Разделён на клиент и сервер.
Каталоги скиллов, например
[agent-skills](https://gitea.example.org/dim/agent-skills),
хранят свой реестр `sources.json` и развёрнутую копию клиента.

## Клиент — `client/`

Эталонные установщики Linux/Windows и их вспомогательные скрипты. Сервер
копирует их в корень обслуживаемого каталога. Затем каждый компьютер
клонирует только каталог и запускает `install.sh` или `install.ps1`.
Для установки клиенту не нужен доступ к этому репозиторию updater.

Клиент ежечасно получает каталог, скачивает закреплённые версии скиллов,
проверяет SHA256 и подключает пользовательские ссылки в `.agents/skills`
и `.claude/skills`. Python ему не нужен: Linux использует Bash/jq и обычные
утилиты; Windows — PowerShell, Git и штатные curl.exe/tar.exe.
Подробности: [документация клиента](client/README.md).

Изменения установщиков делайте в `client/`, а не в их развёрнутых копиях.
Сервер сверяет хеши управляемых файлов, обновляет изменившийся эталон и
сохраняет `.agent-skills-client.json` в каждом каталоге. Ручные изменения
копии вызывают конфликт и сохраняются. LF/CRLF не вызывают ложного обновления.

## Сервер — `server/`

Запускается на i3Ubuntu. Читает [список каталогов](server/catalogs.json),
проверяет путь, origin, ветку, upstream и чистоту каждой рабочей копии.
Обновляет клиентские файлы и проверяет источники из реестра каталога.
Разрешённые новые версии закрепляет в реестре и публикует вместе с изменениями
клиента. Файлы самих скиллов остаются в их источниках и локальном кеше.

Для Git-источника проверяется commit выбранной ветки/тега, затем структура
папки и SHA256 всех файлов. Для одиночного HTTPS-файла проверяется SHA256
содержимого. Изменение вне папки скилла не меняет закреплённую версию.
`auto_update=false` оставляет новую версию в отчёте до ручного одобрения.
Техническая проверка не анализирует смысл инструкций; это можно поручить
управляющему скиллу. Команды импортируемого скилла при проверке не выполняются.

При ошибке одного каталога остальные продолжают обслуживаться. Сервер и
клиент блокируют одну и ту же рабочую копию на время операции. Локальные
правки, расхождение истории и неопубликованные ручные коммиты сохраняются.
Неудачный push автоматического коммита повторяется при следующем запуске.

## Команды на i3

Нужны Python 3.9+ (стандартная библиотека), Git, Bash, flock и пользовательский
systemd. Настройте Git identity и доступ к updater и каталогам без запроса
пароля. Пути в `server/catalogs.json` относительны к этому файлу.
Каталог должен быть отдельной Git-копией с `sources.json` версии 2 и
настроенным origin/upstream; его URL и ветка задаются в конфигурации.

```bash
python3 server/manage.py status
python3 server/manage.py maintain --dry-run
python3 server/manage.py maintain --apply-auto --publish
```

`maintain` без `--publish` оставляет изменения клиента/реестра для просмотра
в рабочей копии каталога. `--dry-run` не меняет клиент/реестр и не делает pull;
он может обновить локальный кеш и отчёт. `status` проверяет локальные копии.
Для обслуживания только одного каталога добавьте `--catalog agent-skills`
перед подкомандой.

Обновить только развёрнутые клиентские скрипты:

```bash
python3 server/manage.py --catalog agent-skills deploy-client --publish
```

Зарегистрировать источник и закрепить первую версию:

```bash
python3 server/manage.py --catalog agent-skills register example-skill --git-url https://example.org/owner/repo.git --path skills/example-skill --ref refs/heads/main --auto-update no --publish
```

Для одиночного SKILL.md используйте `--url https://.../SKILL.md` вместо
Git-параметров. Предпочитайте постоянный версионный URL: изменённый файл не
позволит новому клиенту скачать прежнюю закреплённую версию. Локальным файлам
и архивам сначала нужен опубликованный источник содержимого; payload не
добавляется ни в updater, ни в реестр-каталог.

Проверить доступные версии без одобрения и затем принять выбранную:

```bash
python3 server/manage.py --catalog agent-skills check
python3 server/manage.py --catalog agent-skills approve example-skill --revision <revision-из-отчёта> --publish
```

Отчёт находится в `.git/skill-updates.json` соответствующего каталога.
Если источник изменился после просмотра revision, одобрение останавливается
до повторного анализа. Прямой `server/skills.py --catalog PATH` — низкоуровневый
инструмент регистрации/проверки; обычные операции выполняйте через manage.py.

## Расписание

```bash
bash server/install.sh
systemctl --user start agent-skills-updater.service
systemctl --user list-timers agent-skills-updater.timer
journalctl --user -u agent-skills-updater.service -n 30
```

Ежедневная задача сначала обновляет чистую копию updater, затем выполняет
`maintain --apply-auto --publish` для всех каталогов. Настройка публикации
повторяет обычную Git-авторизацию пользователя. Отключение:
`bash server/install.sh --uninstall`. Пользовательский systemd должен быть
активен; для работы после выхода требуется отдельно настроенный linger.

Ежечасные клиентские таймеры устанавливаются в каталогах как прежде. Старый
`agent-skills-check.timer` заменён на `agent-skills-updater.timer`; серверный
код больше не копируется в каталог. Планировщик T3 для этих задач не нужен.

## Управляющие скиллы и тесты

Полные инструкции находятся в `server/skills/`, точки обнаружения Codex —
в `.codex/skills/`. Сюда перенесены `add-shared-skill`, `check-skill-updates`
и прежний Fleet-скилл `add-fleet-skill`; добавлен `maintain-skill-catalogs`.
Они действуют только в проекте updater, глобально не устанавливаются.

Проверки: `python3 -m unittest discover -s tests -v`. Если доступен pwsh,
проверяются также PowerShell-синтаксис, скачивание и совместимость хешей.
Переносной runtime можно задать через `AGENT_SKILLS_PWSH=/path/to/pwsh`.
Это не заменяет проверку junctions и Планировщика на Windows.
