# Каталог общих скиллов

`sources.json` содержит источники и закреплённые версии скиллов.
Клиентские файлы поставляет
[agent-skills-updater](https://gitea.example.org/dim/agent-skills-updater).
Редактируйте установщики в его папке `client/`: сервер сам перенесёт обновления
сюда. `.agent-skills-client.json` хранит хеши управляемых файлов.

## Подключение компьютера

Клонируйте этот каталог под пользователем, который запускает агентов.
Linux: нужны Git, Bash, jq, curl, tar, sha256sum, find, sort, flock и
пользовательский systemd. Ubuntu: `sudo apt install git jq curl tar coreutils findutils util-linux`.

```bash
bash install.sh
```

Windows 10/11: нужны Git, PowerShell 5.1+ и штатные curl.exe/tar.exe.
Используйте локальный диск. Администратор и Developer Mode не требуются.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Python клиентам не нужен. Установщики подключают скиллы и настраивают запуск
раз в час. Linux-таймер работает, пока активен пользовательский systemd
(работа после выхода требует отдельно настроенного linger). Windows-задача
работает, пока пользователь вошёл в систему. WSL подключается отдельно
Linux-установщиком. Доступ Git в фоне должен работать без запроса пароля.

## Что обновляется

Клиент получает каталог через `git pull --ff-only`, скачивает только версии
из реестра и проверяет SHA256. Ветку источника для выбора новых версий клиент
не проверяет. Скиллы остаются в пользовательском кеше:
`~/.cache/agent-skills/versions/` на Linux (или `$XDG_CACHE_HOME`),
`%LOCALAPPDATA%\agent-skills\versions\` на Windows.

В `~/.agents/skills/<name>` и `~/.claude/skills/<name>` создаются ссылки в кеш
(на Windows — junctions). Чужие установки сохраняются с сообщением о конфликте; локальные правки
публикуются в общий каталог по правилам ниже. При ошибке загрузки или несовпадении хеша прежняя
установка остаётся. Для одиночного SKILL.md нужен версионный HTTPS URL:
изменяемый URL может больше не отдавать закреплённую версию.

## Ваши правки распространяются на остальные станции

Редактируйте файлы через `.agents/skills/<name>` или `.claude/skills/<name>`.
При следующей успешной синхронизации клиент публикует полный снимок вашей
доработки в `customizations/<name>/<SHA256>/` этого каталога и обновляет
`customization` в реестре. Остальные компьютеры получают его при своей
синхронизации. Можно запустить вручную: `bash install.sh --sync-only` или
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Mode Sync`.
Для публикации нужен доступ Git на запись. `--link-only` / `-Mode Link`
работает локально и не отправляет правки.

Исходный скилл остаётся зарегистрирован с прежней revision и хешем.
Когда внешнее содержимое изменится, сервер сообщит `upstream-conflict` и
сохранит общую доработку до ручного решения. Сравнение и команды
`resolve --strategy keep-shared|take-upstream` описаны в README updater.
Добавленные и удалённые файлы входят в вашу общую версию. Удаление всего
скилла или `SKILL.md` не публикуется как удаление скилла.

Одновременные правки одной старой версии на разных компьютерах не
перезаписывают друг друга: вторая станция сообщает `SHARED CONFLICT` и
сохраняет свои файлы. При отклонённом push локальный коммит остаётся;
сетевой сбой повторяется автоматически, расхождение истории требует
ручного разбора. Неопубликованные ручные Git-коммиты клиент не отправляет.
Уже опубликованная старая изменённая копия после переключения ссылок
переносится в `local-history/` внутри кеша. Не редактируйте исторические
копии: для новой правки используйте текущую ссылку.

Ссылки внутри скилла, `.git`, `.gitattributes` и несовместимые с Windows
пути в публикуемых доработках не поддерживаются. SHA256 проверяет точные
байты, включая CRLF и бинарные файлы. Снимки в каталоге не редактируйте.

Новые инструкции надёжно обнаруживаются в новом сеансе агента. Совместимость
самих инструкций с каждым агентом и ОС проверяется отдельно. Техническая
проверка структуры и SHA256 не является оценкой безопасности инструкций.

## Управление

Linux: `bash install.sh --sync-only`, `--link-only` (без Git pull),
`--uninstall` (отключить расписание, сохранив ссылки).
Состояние: `systemctl --user list-timers agent-skills.timer`;
журнал: `journalctl --user -u agent-skills.service -n 30`.

Windows: `install.ps1 -Mode Sync`, `-Mode Link` или `-Mode Uninstall`.
Состояние: `Get-ScheduledTask -TaskName 'AgentSkills-Hourly-*' | Get-ScheduledTaskInfo`.

Локальные изменения Git и расхождение истории требуют ручного решения;
клиенты ничего не сбрасывают. Удаление записи оставляет старую ссылку для
ручного удаления. Для переноса рабочей копии исправьте ссылки и повторите
установку, чтобы обновить путь в задании.

## Добавление и проверка скиллов

Этим занимается серверная часть `agent-skills-updater` на i3. Управляющие
скиллы и тесты находятся там. Сервер ежедневно проверяет источники,
публикует разрешённые новые версии реестра и обновляет клиентские файлы.
Записи с `auto_update=false` остаются на прежней версии до ручного одобрения.
