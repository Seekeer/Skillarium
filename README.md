# Agent Skills

Реестр версий общих скиллов и скрипты их доставки для Codex, OpenCode и
Claude Code. [Приватный репозиторий](https://gitea.example.org/dim/agent-skills).
Содержимое скиллов хранится в исходных репозиториях, вне этого репозитория.

## Как проверяются обновления

Проверка источников запускается только на i3Ubuntu отдельным
`check-updates.sh`. По умолчанию он лишь составляет отчёт. В ежедневном
режиме `--apply-auto` обновляет разрешённые записи и публикует реестр.

Для Git-источника скрипт вызывает `git ls-remote` для конкретной ветки/тега,
получает commit, скачивает его во временную папку и берёт указанную подпапку
скилла. Проверяет наличие `SKILL.md`, полей `name` и `description`, соответствие
имени записи и допустимые типы/пути файлов. Команды скилла не выполняются.
Ссылки и специальные файлы в импортируемом дереве не поддерживаются.

Скрипт вычисляет общий SHA256 из относительных путей и хешей всех файлов.
Для одиночного HTTPS-файла дополнительно вычисляет SHA256 его байтов.
Если содержимое не изменилось, commit в реестре остаётся прежним: изменения
в других частях исходного репозитория не вызывают обновление скилла.

Если содержимое новое, `auto_update=true` разрешает ежедневному проверяющему
скрипту записать новый `revision` и `content_sha256` в `sources.json`, сделать
commit и push. Для остальных записей новая версия попадает только в отчёт
`.git/skill-updates.json`; закрепление требует `--approve NAME`.

Это техническая проверка структуры и целостности. Она не оценивает смысл
инструкций и качество кода скилла. Для просмотра изменений агентом есть
проектный `$check-skill-updates`. Включение автообновления означает согласие
принимать новые версии этого источника после технических проверок.

## Как устанавливаются версии

Каждый компьютер раз в час получает этот реестр через `git pull --ff-only`,
скачивает только закреплённые версии и проверяет `content_sha256`. Внешние
ветки для выбора обновления клиенты не проверяют. Уже скачанная версия
повторно используется из локального кеша:

- Linux: `${XDG_CACHE_HOME:-~/.cache}/agent-skills/versions/<name>/<hash>/`.
- Windows: `%LOCALAPPDATA%\agent-skills\versions\<name>\<hash>\`.

Из `~/.agents/skills/<name>` и `~/.claude/skills/<name>` создаются ссылки в этот
кеш: символические на Linux, junctions на Windows. Первый каталог используют
Codex/OpenCode, второй — Claude Code. При обновлении переключаются только
ссылки, которыми управляет этот кеш; чужие установки сохраняются. Изменённые
вручную файлы старой установленной версии тоже сохраняются с сообщением о
конфликте. Старые версии автоматически не удаляются.

При недоступном источнике, несовпадении хеша или сломанном `SKILL.md` старая
установка остаётся. Хеш подтверждает соответствие реестру, а не безопасность
содержимого. Удалённые записи оставляют ссылки для ручного удаления.
Для одиночного SKILL.md используйте версионный HTTPS URL: если файл по URL
уже изменился, новый компьютер не сможет получить старую одобренную версию
и остановит установку этого скилла вместо получения иной версии.

## Установка на компьютере

Нужны **Git и Python 3.9+**, без дополнительных Python-пакетов. Доступ к
приватным Git-источникам настройте через обычный SSH-ключ или credential
manager пользователя; фоновые задачи не спрашивают пароли. На Linux нужны
Bash, flock и пользовательский systemd; на Windows — Windows PowerShell 5.1+.

Linux:

```bash
git clone https://gitea.example.org/dim/agent-skills.git ~/Dev/agent-skills
bash ~/Dev/agent-skills/install.sh
```

Windows, локальный диск, без прав администратора/Developer Mode:

```powershell
git clone https://gitea.example.org/dim/agent-skills.git C:\My\Dev\agent-skills
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\My\Dev\agent-skills\install.ps1
```

Установщик сразу выполняет синхронизацию и включает ежечасный запуск.
Linux-таймер работает, пока активен пользовательский systemd; для работы
после выхода нужен отдельно настроенный linger. Windows-задача работает под
вошедшим пользователем и не сохраняет пароль. Для WSL отдельно запускайте
Linux-установщик внутри WSL. Запускайте под пользователем агента.

Локальные изменения реестра/скриптов, detached HEAD и расходящиеся ветки
останавливают Git-обновление без потери данных. Установка уже закреплённых
версий всё равно проверяется. Проверка i3 и клиентский запуск используют
общую блокировку, чтобы не менять рабочую копию одновременно.

## Добавление источника

В проекте доступен `$add-shared-skill`. Для ручной регистрации Git-скилла:

```bash
python3 scripts/skills.py register example-skill --git-url https://example.org/owner/repo.git --path skills/example-skill --ref refs/heads/main --auto-update no
```

Для одиночного файла используйте `--url https://.../SKILL.md` вместо
`--git-url`, `--path` и `--ref`. `--auto-update yes|no` обязателен: управляющий
скилл спрашивает пользователя перед регистрацией. Первая версия скачивается,
проверяется и закрепляется сразу. Сохраняются только метаданные в реестре.
Локальный файл или архив сначала нужно опубликовать в отдельном репозитории
с содержимым скиллов; в этот репозиторий payload не добавляется.

Затем проверьте diff, сделайте commit/push и выполните локальную установку.
Управляющий скилл остаётся проектным в `.codex/skills/`; он не устанавливается
глобально. Реестр имеет формат:

```json
{
  "version": 2,
  "skills": {
    "example-skill": {
      "source": {
        "kind": "git",
        "url": "https://example.org/owner/repo.git",
        "path": "skills/example-skill",
        "ref": "refs/heads/main"
      },
      "auto_update": false,
      "revision": "<полный SHA commit>",
      "content_sha256": "<SHA256 дерева скилла>"
    }
  }
}
```

## Управление

Клиент Linux:

```bash
bash install.sh --sync-only
bash install.sh --link-only  # установить версии из локального реестра без git pull
systemctl --user list-timers agent-skills.timer
journalctl --user -u agent-skills.service -n 30
bash install.sh --uninstall  # отключить доставку; ссылки сохраняются
```

Клиент Windows: `install.ps1 -Mode Sync`, `-Mode Link` или `-Mode Uninstall`.
Состояние: `Get-ScheduledTask -TaskName 'AgentSkills-Hourly-*' | Get-ScheduledTaskInfo`.

Проверяющий компьютер i3, из чистой опубликованной рабочей копии:

```bash
bash check-updates.sh                     # только отчёт
bash check-updates.sh --apply-auto        # применить разрешённые и опубликовать
bash check-updates.sh --install-timer     # ежедневная проверка на этом компьютере
systemctl --user list-timers agent-skills-check.timer
journalctl --user -u agent-skills-check.service -n 30
bash check-updates.sh --uninstall-timer
```

Ручное одобрение после просмотра отчёта:

```bash
python3 scripts/skills.py check --approve example-skill --expected-revision <revision-из-отчёта> --publish
```

`--publish` требует чистой рабочей копии, настроенных Git identity и upstream;
коммитит только реестр. Запуск без `--publish` сохраняет изменения локально.
При сбое push локальный commit сохраняется, а следующий запуск повторяет push.
Таймер проверки устанавливайте только на i3; клиентский таймер — на каждом ПК.
Планировщик T3 и запуск модели для регулярных проверок больше не нужны.

Проверки: `python3 -m unittest discover -s tests -v`. На Windows Python
запускается через `py -3`, либо `python.exe`, если launcher не установлен.
