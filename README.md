# Общие скиллы

Единый Git-репозиторий библиотеки: готовые папки `skills/<name>/`, реестр
`sources.json`, общая конфигурация `agent-skills.json`, нативные клиенты
Linux/Windows и серверная часть (`server/`). Отдельный репозиторий
agent-skills-updater больше не нужен: его история сохранена в этом.

Все автоматические публикации идут через ветки `agent-skills/...` и pull
request с автоматическим слиянием. Основная ветка защищена, прямой push в неё
не выполняется. Правки скиллов принимаются от любой подключённой машины после
технических проверок; закрепления внешних версий, политики и базы `upstream/`
принимаются только от машины, назначенной сервером в `agent-skills.json`.

## Подключение компьютера

Клонируйте репозиторий под пользователем, запускающим агентов. На Linux нужны
Git, Bash, jq, curl, flock и обычные утилиты файловой системы:

```bash
bash install.sh
```

На Windows 10/11 нужны Git, PowerShell 5.1+ и Windows Script Host с VBScript.
Используйте локальный диск; администратор и Developer Mode не требуются:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик создаёт ссылки `.agents/skills/<name>` и `.claude/skills/<name>`
прямо на `skills/<name>/` (в Windows — junctions) и включает ежечасную
синхронизацию. Python клиенту не нужен; клиент не обращается к внешним
источникам. Git и API хостинга должны работать без запроса пароля: клиент
берёт учётные данные из Git credential helper (тот же токен, что для push,
с правом записи в репозиторий).

Имя машины берётся из `git config agent-skills.machine`, иначе из имени
компьютера. Имена должны различать установки (например, Windows и WSL на одном
компьютере): `git config agent-skills.machine laptop-wsl`. Адрес API выводится
из origin; другой задаётся `git config agent-skills.api <url>/api/v1/repos/<owner>/<repo>`.

Linux-таймер работает при активном пользовательском systemd; для работы после
выхода нужен linger. Windows-задача работает при входе пользователя и запускает
`scripts/sync-hidden.vbs` через `wscript.exe` со скрытой консолью; очередной
`-Mode Sync` переводит старую задачу на этот запуск, сохраняя расписание.
Не переносите Git-копию без исправления ссылок и расписания.

## Правки скиллов

Редактируйте установленный скилл через `.agents/skills/<name>` или
`.claude/skills/<name>` — это файлы Git-копии. При синхронизации клиент
коммитит изменения папок `skills/<name>/` от имени `agent-skills/<машина>`,
объединяет их с основной веткой во временной рабочей копии, отправляет ветку
`agent-skills/sync/<машина>-<id>` и создаёт или обновляет один PR с
автослиянием. Подтверждать ничего не нужно; хостинг запускает проверки и
принимает PR. Остальные станции получают принятый результат при своей
синхронизации. Личные настройки автора Git не меняются.

Новая папка `skills/<name>/` с корректным `SKILL.md` (frontmatter с тем же
`name` и `description`) публикуется так же, без записи в реестр: сервер
зарегистрирует её как собственный скилл при очередном обслуживании.

Автоматически не публикуются: staged-файлы, неопубликованные ручные коммиты,
изменения вне `skills/<name>/` (код клиента, сервер, документация), файлы по
правилам Git ignore. Некорректный `SKILL.md`, несовместимые с Windows пути
(device names вроде `CON`, `AUX`, `COM1`, символы `< > : " \ | ? *`,
завершающие точки/пробелы, коллизии регистра) и удаление всего скилла дают
понятный отказ; файлы остаются на месте. Удаление скилла целиком — явная
административная операция.

При конфликте параллельных правок локальный коммит сохраняется, маркеры
слияния в установленные файлы не попадают. Rebase, reset и force-push не
используются. Без сети скиллы продолжают работать, правки сохраняются в
локальном коммите и публикуются при следующей синхронизации; повтор находит
уже отправленную ветку и PR и не создаёт дубликатов.

## Внешние обновления

Внешние источники проверяет только назначенный сервер. Для каждого внешнего
скилла задана политика (`auto_update` в реестре):

- `auto` — совместимое обновление, в том числе чистое объединение с вашими
  доработками, применяется автоматически; вопрос возникает только при конфликте;
- `confirm` — каждое обновление ждёт вашего подтверждения.

Ожидающие обновления — ветки `agent-skills/update/<name>/<ключ>` с PR без
автослияния. Активные установки, включая серверную, до принятия не меняются.
Работайте с ними на любом клиенте (или попросите агента — скилл
`review-skill-updates`):

```bash
bash install.sh --updates
bash install.sh --review <skill>
bash install.sh --approve <skill> <commit>
bash install.sh --resolve <skill> <commit> keep-ours|take-upstream|merged
```

```powershell
.\install.ps1 -Mode Updates
.\install.ps1 -Mode Review -Skill <skill>
.\install.ps1 -Mode Approve -Skill <skill> -Commit <commit>
.\install.ps1 -Mode Resolve -Skill <skill> -Commit <commit> -Strategy keep-ours
```

`--review` показывает итоговый diff относительно текущей общей версии и
готовит копию для разбора в `.git/agent-skills-review/<skill>` (вне
установки; при конфликте — с маркерами). Одобряется точный показанный коммит:
если предложение, общая папка или входящая версия изменились, команда
откажет, а сервер подготовит новое предложение. Для `merged` отредактируйте
файлы в копии разбора и уберите маркеры. Отвязка от источника (`detach`)
выполняется на сервере: `python3 server/manage.py resolve`.

## Управление

Linux: `bash install.sh --sync-only`, `--link-only` (без Git-синхронизации),
`--status` (машина, сервер, ожидающая публикация и причина, предложения),
`--uninstall` (отключает расписание, сохраняя ссылки).
Windows: `install.ps1 -Mode Sync`, `-Mode Link`, `-Mode Status`, `-Mode Uninstall`.

Linux-журнал: `journalctl --user -u agent-skills.service -n 30`;
расписание: `systemctl --user list-timers agent-skills.timer`.
Windows: `Get-ScheduledTask -TaskName 'AgentSkills-Hourly-*' | Get-ScheduledTaskInfo`.

Чужие установки и ссылки сохраняются с сообщением о конфликте. Ссылки старого
клиента на кеш `versions/<name>/<hash>` переводятся на папки библиотеки,
совместимые доработки кеша импортируются; сам кеш не удаляется. Git сохраняет
точные байты, CRLF, бинарные файлы и права исполнения; Git-метаданные и
вложенные ссылки внутри скиллов не поддерживаются.

Сервер, назначение роли, правила PR и миграция описаны в
[server/README.md](server/README.md).
