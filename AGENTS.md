# Skillarium

Репозиторий движка: нативные клиенты (`install.sh`, `install.ps1`,
`scripts/`), сервер (`server/`), приложение (`app/`), шаблон библиотеки
(`templates/library/`) и сборка выпусков (`release/`). Установка и
обновление — `scripts/skillarium.*` (они же загрузочные скрипты выпуска),
установка сервера — `server/setup.*`, клиента — `scripts/setup-client.*`,
мост старой раскладки — `scripts/bridge.*`, переход библиотеки —
`release/migrate_library.py` и [docs/migration.md](docs/migration.md). Библиотека скиллов
пользователя (`skills/<name>/`, `sources.json`, `agent-skills.json`,
`upstream/<name>/`) — отдельный репозиторий; здесь её нет, тесты создают
временные библиотеки из шаблона. История agent-skills и agent-skills-updater
сохранена.

Все автоматические публикации идут через ветки `agent-skills/...` и PR с
автослиянием; прямой push в `main` запрещён. Правки скиллов принимаются от
любой машины; закрепления, политики, `upstream/` и прочее серверное состояние —
только от коммитов служебного автора `agent-skills/<server.machine>`
назначенного сервера (правило: `server/policy.py`). Назначение сервера меняется
только `manage.py assign-server`. Не меняй личные настройки автора Git
пользователя: служебная идентичность задаётся на одну команду.

Новый скилл добавляет `skillarium add <ссылка или папка>` (`manage.py add`);
обновления и конфликты разбирает встроенный скилл
[review-skill-updates](client/skills/review-skill-updates/SKILL.md). Команды и
границы автоматизации: [README.md](README.md), [server/README.md](server/README.md).

Без явной просьбы пользователя не выпускай движок (тег `v<версия>`), не
выбирай и не меняй назначенный сервер, не меняй настройки хостинга `main`
(проверяй их на отдельном тестовом репозитории) и не архивируй прежние
репозитории. Ручные правки клиентских копий на станциях не затирай
reset/clean: сравни с эталоном и перенеси нужное.

Клиентам Python не нужен; Python нужен только исполнителю серверной логики.
Изменения клиентских файлов делай в корне и обновляй
`python3 server/manage.py client-manifest --write`; новые клиентские файлы
добавляй в `CLIENT_FILES` (server/absorb_updater.py). Изменения кода и
документации не попадают в автоматические клиентские коммиты — сохраняй это.
Движок не должен считать свою папку библиотекой: путь библиотеки
передаётся явно (`--library`/`-Library`/`--repo`, `SKILLARIUM_LIBRARY`,
конфиг Skillarium), а файлы движка берутся из папки скрипта. Единственное
исключение — старая раскладка, где движок лежит внутри библиотеки: её папка
проверяется после явных путей и до конфига, пока идёт миграция (этап 7 плана). Формат
библиотеки (`format` в `agent-skills.json`) поднимается только вместе с
`supported_format` в `scripts/locate.*` и `SUPPORTED_FORMAT` в
`server/hosting.py`. План распространения:
[.scratch/skillarium-distribution/plan.md](.scratch/skillarium-distribution/plan.md).
Интерфейсы ссылок расширяемы (`link_roots`/`Get-LinkRoots`) для проектных
подключений.

Сохраняй чужие установки, локальные правки, staged-файлы, ручные коммиты,
историю, реестр и ручные изменения клиентских копий. Rebase, reset,
force-push и очистка пользовательской работы не являются способом
восстановления.

Проверяй на временных Git-каталогах с локальным bare remote, имитацией
хостинга `tests/fake_hosting.py` (настоящая проверка `server/policy.py`,
защита `main` хуком) и временными HOME/кешами; реальные пользовательские
каталоги не используй. Правила PR на настоящем Gitea проверяй в отдельном
тестовом репозитории. Установку из выпусков и настройку Gitea проверяй
имитациями `tests/fake_releases.py` и `tests/fake_gitea.py`; реальные PATH,
профиль и хранилище учётных данных пользователя не трогай (тесты задают
`SKILLARIUM_HOME`, `APPDATA`, `GIT_CONFIG_GLOBAL`). Синхронизации старой
раскладки в тестах идут с `SKILLARIUM_NO_BRIDGE=1`, кроме `test_bridge.py`. Linux-клиент проверяется на Linux (jq, flock, curl);
junction и Планировщик — только нативно на Windows (`tests/README.md`).
